Step 3 of 4: the finding and filter headers

Email Header Decoder

Paste headers and read what failed and why.

Nothing you paste leaves your browser. Read how.

This page has no server behind it. The headers you paste are read by code running on this page, in your browser, and are never sent, stored, or logged anywhere.

It makes no network requests at all: no fonts, no analytics, no DNS lookups. When the page is opened as its own file, its Content Security Policy has no connect-src, so the browser itself blocks any attempt to send data out.

Load sample:

Gmail: More, Show original, Copy to clipboard. Outlook: File, Properties, Internet headers. Outlook on the web: More actions, View, View message source. Apple Mail: View, Message, Raw Source.

Reads the headers as the receiving servers wrote them. It makes no network requests, queries no DNS and verifies no signatures, and it never sends what you paste anywhere.

Received dates follow RFC 5322, including the obsolete zones; a zone it cannot trust is read as UTC and marked. TLS is taken from each hop's with clause (RFC 3848) and the comments around it.

Alignment uses the SPF and DKIM results the receiver reported (RFC 8601) and checks each identifier against the From domain itself (RFC 7489). The organizational domain comes from a short built-in suffix list, not DNS, and the page marks it when that is a guess. ARC (RFC 8617) is checked for structure only; seals are not verified.
